# ETF 유니버스 패널: `start`/`end` 는 **유니버스·membership 에도** 걸린다 (캐리인 1행 포함)

`QuantDB.fetch_etf_universe_panel(start=..., end=...)` 은 원래 창을 **가격 패널에만** 넘겼다. 유니버스(어떤 종목을 담을지)와 membership 은 항상 전 이력이었다. 그 결과 한 번의 호출이 서로 다른 시간축의 산출물 둘을 돌려줬다.

SPY+QQQ, `start='2015-01-01'` 실측 (2026-08-27):

| | 변경 전 | 변경 후 |
|---|---|---|
| membership | (320, 1227) · 1999-12-31 ~ 2026-07-31 | (140, 801) · **2014-12-31** ~ 2026-07-31 |
| panel | 2751열 = 917 tid × 3 item | 2400열 = 800 tid × 3 item |
| 공통 tid | 797 | **799** |
| membership 에만 | 311 (그중 310은 마지막 편입이 2015 이전) | 2 |
| 패널에만 | 120 (2015 전 편출, 아직 거래 중인 옛 구성종목) | 1 |
| 창 안 all-False 컬럼 | 428 | 0 |

세 숫자가 어긋난 이유는 각각 다른 필터를 통과했기 때문이다. 브리지 tid 1,230 중 가격 행이 하나라도 있는 것은 1,224 지만 **2015 이후** 행이 있는 것은 917 뿐이고, membership 은 창을 아예 안 봤다.

## Decision

창을 유니버스 SQL 과 membership SQL 에 **똑같이** 건다. 단 하한은 `start` 가 아니라 **`start` 이하의 마지막 `month_end`(캐리인 1행)** 다:

```sql
SELECT max(h.month_end) FROM ai_ready.etf_global_holdings_monthly h
WHERE h.fund = ANY(:f) AND h.row_type = 'month_end' AND h.month_end <= :s
```

가격 패널은 캐리인이 아니라 `start` 그대로 자른다 — 구성원을 한 달 더 아는 것과 가격을 한 달 더 받는 것은 다른 문제다.

캐리인이 필요한 이유는 정렬이다. `month_end` 는 다음 달을 지배하므로, 하한을 `>= start` 로 엄격히 잡으면 `start=2015-01-01` 일 때 첫 행이 2015-01-31 이 되어 **2015년 1월 한 달이 구성원 미상**이 된다. 실측으로 `membership.reindex(panel.index, method='ffill')` 의 2015-01-02 가 캐리인 있음 → 527 True, 없음 → 전부 NaN 이다. 캐리인은 창보다 **과거** 행이므로 선견편향이 아니다.

## Considered Options

- **그대로 두고 호출자가 `membership.loc[start:]` 로 자르기** — 기각. 기본값이 틀린 상태로 남는다. 실제로 이 ADR 은 "왜 패널은 917 인데 membership 은 1227 인가" 라는 질문에서 시작했다. 게다가 잘라도 패널에는 창 안에서 한 번도 편입된 적 없는 종목 120개가 그대로 남는다 — 호출자가 지울 수 없는 오염이다.
- **행만 자르고 유니버스는 전 이력 유지** — 기각. 위의 120개가 남는다. 창을 준 사용자가 기대하는 유니버스가 아니다.
- **하한을 `>= start` 로 엄격히** — 기각. 위 1월 공백.
- **all-False 컬럼을 사후 제거하는 로직 추가** — 불필요. 창 안 행으로만 피벗하면 모든 컬럼이 최소 1개의 True 를 갖는다 (죽은 컬럼이 **생길 수 없다**). 실측 0개.
- **membership 을 패널 날짜축에 아예 정렬해서 반환** — 여전히 기각. ADR-0005 의 근거(공시 지연 미상 → 선견편향 결정을 라이브러리가 조용히 내리게 됨) 그대로다. 창을 맞추는 것과 축을 맞추는 것은 다르다.

## Consequences

- **`start` 를 주면 생존편향의 성격이 바뀐다.** 유니버스가 "창 안에 한 번이라도 편입된 종목" 이 된다. 전 이력 합집합(창 밖에서만 편입됐던 종목까지)이 필요하면 `start=None` 이다.
- **캐리인 조회로 `read_sql` 이 한 번 늘어난다** (`max(month_end)`, 월말 인덱스 스캔). `start=None` 이면 아예 안 돈다.
- **`start` 가 홀딩스 시작(1999-12)보다 앞서면 하한이 없다** — `max()` 가 NULL 이므로 조건을 붙이지 않는다.
- **ADR-0005 의 "membership 컬럼마다 대응하는 패널 컬럼이 반드시 있다" 는 정정된다.** 부분집합인 것은 *패널 컬럼* 이 아니라 *패널 조회에 넣은 브리지 tid 목록* 이다. 창 여부와 무관하게 양방향으로 어긋난다 (변경 후에도 membership 에만 2, 패널에만 1).
- 창이 홀딩스 기간 밖이면 유니버스가 비고 `ValueError` 가 난다 — 메시지에 `start`/`end` 를 같이 적는다.
